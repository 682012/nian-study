# V8.3 AI 与语音实现说明

## 对话链路

- `local`：客户端请求同源 `/api/nian/respond`，失败后使用浏览器内置规则。
- `openai-proxy`：客户端请求同源 `/api/nian/ai`；Worker 只转发到 `https://api.openai.com/v1/chat/completions`。
- `custom-direct`：浏览器直接请求用户填写的 OpenAI-compatible Chat Completions 地址，受目标服务 CORS 规则约束。

对话只发送最近 8 条截断历史、当前消息、错题摘要和学习汇总，不发送完整本地学录。Worker 限制请求为 JSON、32KB、同源/同站，并对模型名、内容长度、超时和上游响应大小做校验。

## Key 策略

- 源码中没有可用 API Key。
- `OPENAI_API_KEY` Worker Secret 可作为站点统一 Key。
- 浏览器填写的 Key 默认放在 `sessionStorage`；主动勾选记住才写入 `localStorage`。
- Worker 不保存浏览器 Key，不把上游错误正文回传给客户端。
- 自定义服务由浏览器直连，Key 不经过本站 Worker。

## 语音链路

`public/assets/nian-voice-v1.js` 负责 Web Speech 音色等待、语言匹配、长句拆分、顺序队列、取消和状态回调。它必须先于百戏楼和陪学面板脚本加载。

系统语音是默认方案。云端模式使用 OpenAI-compatible `/audio/speech`，Worker 代理同样只允许官方 OpenAI；自定义 Speech 地址由浏览器直连。云端失败会尝试系统语音。

## 默认发音（V9.1 起）

系统语音不可用且浏览器未配置任何云端提供商时，`/api/nian/tts` 不再要求客户端提供 Key，而是回落到站点内置默认发音：Worker 使用 `MIMO_API_KEY` Secret 调用小米 MiMo TTS（`mimo-v2.5-tts`，音色"冰糖"）。该 Key 只存在于 Worker Secret，不进入源码与浏览器。陪学面板同时监听 `nian:english-speech` 事件，闪卡系统发音失败后自动改用云端默认发音。

## 直连加速（V9.2 起）

Worker 代理跨境回源小米约增加 7 秒，浏览器直连小米约 1 秒。因此陪学面板首次需要默认发音时请求同源 `/api/nian/voice-key`（Key 仍只存于 Worker Secret），拿到配置后直接调用小米 `chat/completions` 并本地解码 base64 音频；直连失败自动回落 Worker 代理路径。生成的音频按文本缓存在 Cache API 与内存中，重复播放零请求。注意：直连意味着 Key 会到达浏览器，任何访客理论上都可提取；如需收紧，应在小米控制台创建 TTS 专用 Key 并通过 `wrangler secret put MIMO_API_KEY` 轮换。

## Edge TTS 默认嗓子（V9.3 起）

默认发音切换为微软 Edge 神经音色（英文 `en-US-AvaNeural`，中文 `zh-CN-XiaoxiaoNeural`）。链路：同源 `/api/nian/edgetts` → Worker（`EDGE_TTS_TOKEN` Secret）→ `http://tts.682012ysh.loc.cc`（US Caddy）→ autossh 隧道 US:12006 → HB:2006 桥（`engine=edge` 直出，带 `x-bridge-token` 校验）。整条链路没有任何 Key 暴露到浏览器；MiMo 直连降级为第二回落，Worker 代理默认发音为最终兜底。

## 测试

- `tests/worker-api.test.mjs`：输入限制、同源保护、AI 代理、错误脱敏和音频流。
- `tests/voice-controller.test.mjs`：延迟音色、语言选择、长句拆分、状态和停止队列。
- `tests/ai-voice-integration.test.mjs`：配置 UI、无硬编码 Key、用户手势、加载顺序和 Service Worker 缓存。
- `tests/content-v8.test.mjs`：原题库与自适应能力回归。

执行 `bash verify.sh` 可完成全套离线验证。
